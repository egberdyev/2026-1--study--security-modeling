вероятностного моделирования случайных процессов в контексте
кибербезопасности \[1\].

- пуассоновский поток событий как модель потока атак;

  между ними;
- методы оценки вероятности редкого события — теоретический и
  эмпирический;
- поведение статистической оценки при росте объёма выборки.

# Теоретическое введение

## Пуассоновский поток событий

Поток атак на сервер моделируется пуассоновским процессом — случайным
процессом, описывающим поток событий, наступающих независимо друг от
друга с постоянной интенсивностью $\lambda$ \[2\].

Число событий $N(T)$ за интервал длины $T$ подчиняется распределению
Пуассона:

<span id="eq-poisson">$$
P\{N(T) = k\} = \frac{(\lambda T)^k}{k!}\, e^{-\lambda T},
\qquad k = 0, 1, 2, \ldots
 \qquad(1)$$</span>

Математическое ожидание и дисперсия числа событий совпадают:

<span id="eq-moments">$$
\mathrm{E}[N(T)] = \mathrm{D}[N(T)] = \lambda T .
 \qquad(2)$$</span>

Равенство (<a href="#eq-moments" class="quarto-xref">ур. 2</a>) даёт
простой практический критерий: если выборочное среднее заметно
отличается от выборочной дисперсии, гипотеза о пуассоновости потока
сомнительна.

## Интервалы между событиями

Пуассоновский процесс допускает эквивалентное описание через интервалы
между соседними событиями. Интервал $\tau$ распределён по показательному
закону \[3\]:

<span id="eq-exp">$$
f_\tau(x) = \lambda e^{-\lambda x}, \qquad x \geqslant 0,
\qquad \mathrm{E}[\tau] = \frac{1}{\lambda} .
 \qquad(3)$$</span>

Показательное распределение — единственное непрерывное распределение,
обладающее свойством отсутствия последействия: вероятность того, что
следующая атака произойдёт в ближайшие $\Delta t$, не зависит от того,
сколько времени прошло с предыдущей. Именно это свойство формализует
предположение о независимости атак.

Два описания процесса сведены в

|----|----|----|----|

## Оценка вероятности редкого события

Практический интерес представляет вероятность перегрузки сервера —
события «более $k$ атак за час». Теоретически она вычисляется через
функцию распределения:

<span id="eq-tail">$$
P\{N > k\} = 1 - \sum_{i=0}^{k} \frac{\lambda^i}{i!}\, e^{-\lambda} .
 \qquad(4)$$</span>

Эмпирическая оценка строится как частота: доля часов в выборке объёма
$n$, в которых число атак превысило порог. По закону больших чисел эта
частота сходится по вероятности к истинному значению
(<a href="#eq-tail" class="quarto-xref">ур. 4</a>) при $n \to \infty$
\[4\]. Стандартная ошибка оценки частоты составляет

<span id="eq-se">$$
\sigma_{\hat{p}} = \sqrt{\frac{p(1-p)}{n}} ,
 \qquad(5)$$</span>

то есть убывает как $1/\sqrt{n}$. Формула
(<a href="#eq-se" class="quarto-xref">ур. 5</a>) даёт масштаб, с которым
следует сравнивать наблюдаемые расхождения.

## Реализация модели потока

Функция `simulate_attacks` возвращает три величины: почасовое число
атак, интервалы между атаками и моменты их наступления
(<a href="#lst-sim" class="quarto-xref">листинг 2</a>). Число атак за
час генерируется напрямую из распределения
(<a href="#eq-poisson" class="quarto-xref">ур. 1</a>), а интервалы — из
распределения (<a href="#eq-exp" class="quarto-xref">ур. 3</a>); тем
самым в коде явно используются оба эквивалентных описания процесса.

<div id="lst-sim">

Листинг 2: Моделирование пуассоновского потока атак

``` julia
function simulate_attacks(λ::Float64, T::Float64)
    hourly_counts = rand(Poisson(λ), floor(Int, T))

    intervals = Float64[]
    total_time = 0.0

    # накапливаем интервалы, пока не выйдем за горизонт наблюдения T
    while total_time < T
        τ = rand(Exponential(1 / λ))
        push!(intervals, τ)
        total_time += τ
    end

    # последний интервал вывел за пределы T — отбрасываем его
    if total_time > T
        pop!(intervals)
    end

    attack_times = cumsum(intervals)

    return (hourly_counts = hourly_counts,
            intervals = intervals,
            attack_times = attack_times)
end
```

</div>

# Ответы на контрольные вопросы

**1. Что такое пуассоновский процесс?**

Случайный процесс, описывающий поток событий, наступающих независимо
друг от друга с постоянной интенсивностью $\lambda$. Число событий за
интервал подчиняется распределению
(<a href="#eq-poisson" class="quarto-xref">ур. 1</a>).

**2. Какими свойствами обладает пуассоновский поток?**

Стационарность (интенсивность постоянна), отсутствие последействия
(события на непересекающихся интервалах независимы) и ординарность
(вероятность наступления двух событий одновременно пренебрежимо мала).

**3. Почему интервалы между событиями распределены показательно?**

Вероятность отсутствия событий на интервале длины $x$ равна
$P\{N(x) = 0\} = e^{-\lambda x}$ по формуле
(<a href="#eq-poisson" class="quarto-xref">ур. 1</a>). Следовательно,
$P\{\tau > x\} = e^{-\lambda x}$, что и есть показательное распределение
(<a href="#eq-exp" class="quarto-xref">ур. 3</a>).

**4. В чём разница между эмпирической и теоретической вероятностью?**

Теоретическая вычисляется аналитически из модели по формуле
(<a href="#eq-tail" class="quarto-xref">ур. 4</a>). Эмпирическая —
частота события в конечной выборке, то есть сама случайная величина со
стандартной ошибкой (<a href="#eq-se" class="quarto-xref">ур. 5</a>).
При корректной модели и большом объёме выборки они близки, что показано
в <a href="#tbl-probs" class="quarto-xref">табл. 2</a> и
<a href="#tbl-conv" class="quarto-xref">табл. 3</a>.

**5. Что утверждает закон больших чисел и как он проявился в работе?**

Частота события сходится по вероятности к его вероятности при росте
числа испытаний. В работе это видно в
<a href="#tbl-conv" class="quarto-xref">табл. 3</a> и на
<a href="#fig-convergence" class="quarto-xref">рис. 2</a>: с ростом $n$
разброс оценки убывает, а сама оценка стабилизируется у теоретического
значения.

**6. Зачем нужен QQ-график?**

Он сопоставляет выборочные квантили с теоретическими. Если точки ложатся
вблизи прямой, распределения согласуются. Это более чувствительный
инструмент проверки, чем визуальное сравнение гистограмм, особенно на
хвостах распределения.

**7. Как результат применяется на практике?**

Оценка $P\{N > k\}$ позволяет обосновать запас производительности
сервера и пороги срабатывания систем обнаружения атак: порог выбирается
так, чтобы вероятность ложного срабатывания на штатном потоке была
приемлемо малой.

# Выводы

В ходе лабораторной работы:

- создан проект DrWatson, реализована модель пуассоновского потока атак
  с параметрами, вынесенными в отдельный словарь;
- функция `simulate_attacks` возвращает почасовое число атак, интервалы
  и моменты наступления событий; результаты сохраняются на диск с именем
  файла, построенным по параметрам;
- вероятность события «более 10 атак за час» оценена двумя способами
  (см. <a href="#tbl-probs" class="quarto-xref">табл. 2</a>);
  расхождение единичной оценки составило $2.7\,\sigma$, что укладывается
  в случайный разброс;
- проверено соответствие числа атак распределению Пуассона, а интервалов
  — показательному распределению (см.
  <a href="#fig-analysis" class="quarto-xref">рис. 1</a>);
- экспериментально подтверждён закон больших чисел: при $n = 10^4$
  отклонение оценки от теоретического значения составило
  $5 \cdot 10^{-6}$ (см.
  <a href="#tbl-conv" class="quarto-xref">табл. 3</a>);
- выполнено параметрическое исследование по интенсивности потока,
  показавшее резко нелинейный рост вероятности перегрузки (см.
  <a href="#tbl-sweep" class="quarto-xref">табл. 4</a>);
- код преобразован в литературный стиль, из него сгенерированы чистый
  код, Jupyter-блокнот и документация Quarto.

Полученная модель корректно описывает случайный поток событий и служит
основой для более сложных моделей, рассматриваемых в последующих работах
курса.
